## 7) تنظيف بيانات الاختبار بأمان
**لم أنشئ أي بيانات في أي نظام حقيقي.** ما يلي لما أنشأتِه أنتِ. **لا تحذفي شيئًا قبل التأكد أنه اختباري، ولا تحذفي حساب مالكة أو مديرة حقيقيين.**
1. **المتصفح (آمن):** سجّلي الخروج. ثم F12 ← Application ← Storage ← **Clear site data** للعنوان `localhost:5173` فقط.
2. **الجهاز (آمن):** احتفظي بـ`.env.local` إن ستكملين الاختبار؛ لا ترفعيه إلى GitHub (مستثنى في `.gitignore`). أوقفي الخادم بـ`Ctrl+C`. المجلدان `node_modules` و`dist` يمكن حذفهما وإعادة إنشائهما.
3. **المعلمات الاختبارية:** لا يمكن حذفها من التطبيق ولا من القاعدة عادةً (مشغّلات `forbid_delete`)، فاكتفي بـ**تعطيلها** من صفحة «المعلمات والأكواد».
4. **الفصول والسنوات الاختبارية:** لا تُحذف؛ الأفضل ألا تُنشأ سنة اختبارية، وإن أُنشئت فاتركيها غير نشطة.
5. **سجل العمليات:** إضافة فقط ومتسلسل بالتجزئة؛ **لا يُنظَّف**. إن أردتِ بدءًا نظيفًا كاملًا قبل البيانات الحقيقية فالطريق الآمن مشروع Supabase اختباري منفصل يُحذف كاملًا، أو سكربت إعادة تهيئة أكتبه بعد موافقتكِ ويُنفَّذ بعد تصدير نسخة. **لا أنفّذه ولا أنصح به دون قرار صريح** (وذكرتِ أنكِ تريدين مشروعًا نهائيًا واحدًا، فاتخذي القرار قبل دخول أي بيانات حقيقية).
6. **مستخدمو Supabase Auth الاختباريون:** من Dashboard ← Authentication ← Users احذفي **فقط** مستخدمي الاختبار الذين لا صف لهم في `staff_profiles`. من له صف لن يُحذف (`ON DELETE RESTRICT`) وهذا مقصود.
7. **R2:** لا كائنات؛ لم يُنشأ شيء.
