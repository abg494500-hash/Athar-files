# محاكي القاعدة لطبقة الخادم — ما هو، وحدوده، وكيف يُبدَّل بـPGlite (A-99)

## لماذا ليس PGlite الآن؟
سجل npm محجوب في بيئة بناء هذه الدفعة (`ENOTFOUND` ثم رفض الوسيط 403)، فلا `@electric-sql/pglite` ولا `pg`. **لم أتحايل على الحجب.** بدلًا من ذلك وُجد في البيئة **PostgreSQL 16 حقيقي** (ثنائيات الخادم)، فاستُعمل نسخةً محلية مؤقتة؛ وهذا أقوى من PGlite من جهة الأمانة (محرك Postgres كامل بمشغّلاته وقيوده وتزامنه الحقيقي)، لكنه يحتاج ثنائيات PostgreSQL على الجهاز.

## المكوّنات
| الملف | الدور |
|---|---|
| `server/db/types.ts` | واجهة `Db`/`SqlClient` الصغيرة (`query`, `exec`, `transaction`) و`DbError` برمز SQLSTATE. الخدمات تعتمد عليها وحدها. |
| `server/db/psqlDb.ts` | **مشغّل اختبار محلي فقط**: عمليات `psql` دائمة، نتائج JSON، بلا shell (يعمل على Windows). حراسات: مضيف محلي فقط (socket أو localhost)، واسم قاعدة يبدأ بـ`athar_test`، وإلا يُرفض عند الإنشاء. |
| `server/test/helpers/testDb.ts` | ينشئ قاعدة `athar_test_svc_*` جديدة: bootstrap ثم 001…004(+005)، يزرع بيانات وهمية، ويحذفها بعد الاختبار. |
| `scripts/local-pg.sh` | يشغّل/يوقف خادمًا محليًا مؤقتًا (`start` / `env` / `stop`). |

تُفعَّل اختبارات القاعدة بالمتغير `ATHAR_TEST_PG` (مسار مجلد socket أو `localhost`) و`ATHAR_TEST_PG_PORT`؛ وعلى خادم TCP يُستعمل `PGPASSWORD`. دونه تُنفَّذ الاختبارات النقية فقط ويظهر للاختبارات القاعدية بند «تخطّي» ناجح شكليًا (لا يعني أنها جُرِّبت).

## حدود صريحة
- دمج المعاملات في النص يتم بتنصيص literal صارم (اختبارات: علامة الاقتباس، NUL، حقن). **مشغّل الإنتاج سيستعمل البروتوكول الموسَّع**، فهذا المشغّل لا يثبت سلامة المعاملات هناك.
- المحاكاة تغطي مشغّلات الجداول والقيود والأقفال؛ **لا تغطي** Supabase نفسها (PostgREST، GoTrue، سياسات التخزين، حدود الاتصالات، `auth.uid()` الحقيقية).
- الأدوار المحاكاة (`service_role`, `authenticated`) تعريفات bootstrap محلية بصلاحيات أنشأها الاختبار؛ صلاحيات Supabase الافتراضية الفعلية لم تُفحص.

## تبديل المشغّل لاحقًا (PGlite أو pg)
اكتبي محوّلًا يحقق `Db`: `transaction(fn)` يبدأ معاملة على اتصال واحد ويمرر `SqlClient` يدعم `query` (يعيد `rows`) و`exec`. بالنسبة إلى PGlite: `db.query(sql, params)` يدعم `$1…` مباشرة، والمعاملة `db.transaction(tx => …)`. يجب أن تُحوَّل الأخطاء إلى `DbError(sqlstate, message)` (حقل `code` في أخطاء pg/PGlite). ثم تُشغَّل **الاختبارات نفسها** (`server/test/uploadService.test.ts`) بتغيير `createTestEnv` فقط. تحذير: PGlite أحادي الاتصال، فاختبارات التزامن الحقيقي (جلسات متوازية) تحتاج Postgres حقيقيًا أو ستتسلسل.
