# تقرير الدفعة (0.6.14، حزمة r23) — إصلاح إخفاقات اختبارات Windows وتحليل ثغرات npm (A-105)

> **الحالة بصدق:** بيئتي ما زالت بلا npm ولا شبكة ولا jsdom ولا vitest (جرّبتُ `npm ci --offline` فرفض `ENOTCACHED`). لذلك **لم أُشغّل `npm run typecheck` ولا `npm test` ولا `npm run build` ولا `npm audit`**؛ ما نفّذته فعليًا هنا مذكور بدقة أدناه، وما سيُثبت الإصلاح هو **تشغيلكِ لـ`npm test`**. لم أتصل بـSupabase ولا Cloudflare، ولم أنفّذ SQL، ولم أنشر، ولا أسرار حقيقية في أي ملف. حزمة r22 محفوظة دون استبدال. **المشروع غير جاهز للمدرسة ولا للنشر.**

## 1) نتائجكِ المُبلَّغ عنها (ليست من تشغيلي)
`npm install` ✅ · `npm run typecheck` ✅ (أي أن صفحات React الجديدة **تُجمَّع** — كان ذلك أكبر مخاطر r21/r22) · `npm test` ❌ **420/449 (29 فاشلًا)** في `compose.test.ts` و`teacherAuth.test.ts` و`edgeBuild.test.ts` · `npm run build` لم يُذكر · `npm audit`: 11 ثغرة.

**تصحيح لتفسيركِ:** الأسرار الاختبارية **لم تكن قصيرة**؛ الشرط الإنتاجي سليم ومطلوب (32 بايتًا) ولم يُخفَّف.

## 3) ما أُصلح فعلًا
1. **بيئة Node لكل اختبارات الخادم:** `// @vitest-environment node` في أول سطر كل ملفات `server/test/*.test.ts` (19 ملفًا) — صحيح لأنها تختبر كود خادم يعمل في Node/Deno لا في متصفح، وهي الوسيلة المدعومة في كل إصدارات vitest.
2. **`src/test/setup.ts`** لا يفترض وجود `window`: أدوات DOM تُحمَّل داخل `if (typeof window !== 'undefined')` (وإلا لكانت كل اختبارات الخادم ستفشل عند الإعداد بعد التغيير 1). اختبارات الواجهة تبقى في jsdom كما كانت.
3. **`edgeBuild.test.ts`** أُعيدت كتابته: بلا `import.meta.url` ولا `URL` ولا `fileURLToPath` (الجذر من `helpers/projectRoot.ts` المبني على `process.cwd()` والصعود حتى `package.json` باسم `athar-frontend`)، **ويتحقق الآن من المحتوى فعلًا:** (أ) المولَّد مطابق للمصدر، (ب) ≥ 30 ملفًا مولَّدًا، كلها بترويسة «مولَّد آليًا»، كل استيراد نسبي ينتهي بـ`.ts`، والاعتمادات الخارجية بالضبط `node:buffer` و`node:crypto` و`node:util`، (ج) **تشغيل عملية Node مستقلة** (`scripts/edge-smoke.mjs`، بلا vitest/jsdom) تحمّل الملفات المولَّدة بالاستيراد الصريح وتتحقق من `/health` و401، (د) نقطة دخول Deno بلا أسرار ولا مفتاح خدمة. يتطلب Node ≥ 22.6 ويفشل برسالة واضحة إن كان أقدم (لا تخطٍّ صامت).
4. **رسالة `assertPepper`:** فصلتُ «ليس Uint8Array» عن «أقصر من 32 بايتًا». **الشرطان كما هما** (نوع صارم + 32 بايتًا)؛ التغيير تشخيصي فقط، وأضفتُ اختبارين: 31 بايتًا تُرفض، و**سر من عالم آخر بطول 32 يُرفض بسبب النوع لا الطول**. اختبارات رفض الأسرار القصيرة والمتطابقة في `compose`/`teacherAuth` باقية كما هي.
5. **سكربتات تفترض مسارات Unix:** `build-edge-function` و`check-code-sql-compat` و`check-no-secrets-in-frontend` كانت تأخذ الجذر من `new URL(...).pathname` (يعطي `/C:/...` على Windows فيكسر المسارات)؛ صارت `fileURLToPath` — **كانت ستفشل عندكِ على الأرجح** عند تشغيلها (وكنتُ طلبتُ منكِ تشغيلها في r22). و`testDb.ts` صار يستعمل `projectRoot()`.
6. **أداة ثغرات npm** (`scripts/summarize-npm-audit.mjs` + `server/tools/auditSummary.ts`) وفق §5.

## 4) الاختبارات: ما نُفِّذ فعلًا مقابل ما لم يُنفَّذ
**نُفِّذ هنا:**
- مشغّل Node البديل: **385/385** (377 + 8 جديدة: 2 pepper، 5 audit، 1 edgeBuild). **ليس vitest.**
- **إعادة إنتاج إخفاقاتكِ بالمحاكاة:** مع `Uint8Array` من عالم آخر ⇒ 26 + 3 = 29 فاشلًا بالرسالة نفسها؛ وبلا محاكاة ⇒ 42/42 ناجحًا في الملفين.

- فحوص ساكنة: `check-test-environments` **4/4 (جديد، وأمسك حذف الوسم عمدًا)**، SQL 39/39 و30/30 و28/28، التوافق مع المخطط، الأسرار 10/10، المولَّد مطابق.
**لم يُنفَّذ:** `npm install`، `npm run typecheck`، `npm test` (vitest)، `npm run build`، `npm audit`، أي كود في Deno/jsdom/Windows، أي SQL، R2، Supabase.
**توقّع غير مُثبَت:** أن يمرّ `npm test` كاملًا (≈ 457 اختبارًا بعد إضافاتي) دون إخفاق. إن فشل شيء فأرسلي سطور `FAIL` وأول إخفاق.

## 5) ثغرات npm الإحدى عشرة
**لا أستطيع تحديدها** (يلزم سجل npm). في `docs/phase5/NPM_AUDIT_AR.md`: جدول الحزم المثبَّتة وتصنيفها إنتاج/تطوير من `package-lock.json`، وما أعرفه من r13 (2 متوسطة في `react-router` 6.30.6، إصلاحها تحديث رئيسي كاسر لـreact-router 7 — **غير مُعاد التحقق**)، وقواعد القرار (لا `--force`، الإنتاج أولًا، الكاسر في فرع منفصل). **الأداة:** `npm audit --json > audit.json` ثم `node --experimental-strip-types --no-warnings scripts/summarize-npm-audit.mjs audit.json` تُنتج لكِ جدولًا عربيًا بالخطورة والنطاق والكاسر وغير الكاسر لكل حزمة، وتخرج بـ1 عند عالية/حرجة في الإنتاج. اختُبرت على تقرير تركيبي فقط. **لم أغيّر `package.json` ولا `package-lock.json`.** أرسلي `audit-summary.md` وأحلّله.
