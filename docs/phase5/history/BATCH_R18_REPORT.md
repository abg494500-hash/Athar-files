# تقرير الدفعة (0.6.9، حزمة r18) — دخول المعلمة، أرشفة ZIP، إفراج المالكة وoverview (A-100)

> **الحالة بصدق:** بيئة هذه الدفعة **بلا PostgreSQL وبلا سجل npm**. لذلك كل ما يمس القاعدة مكتوب ولم يُشغَّل. لم يُلمَس Supabase ولا Cloudflare ولا أي خدمة حقيقية، ولا أسرار في أي ملف. **المشروع غير جاهز للمدرسة ولا للنشر.**

## 1) ما وجدته في r17 وتحققت منه قبل البدء
مطابق لتقرير r17 (الملفات موجودة: `server/db`, `server/services`, `objectKey`, SQL 001–005، حزمة `supabase/`). بيئتي لا تحوي PostgreSQL، فـ**لم أُعد تشغيل** نتائج r17 المعتمدة على القاعدة (190/190 و62/62…)؛ هي من r17 لا من هذه الدفعة. ما أعدتُ تشغيله: مشغّل Node بلا قاعدة (165/165 قبل إضافاتي).

## 3) الاختبارات التي شُغِّلت فعليًا (وما لم يُشغَّل)
- **مشغّل Node:** `sh scripts/node-test-runner/run.sh` ⇒ **223/223** (165 سابقة + 18 أرشفة + 33 دخول + 7 إفراج/overview/نائبان). **تنبيه مهم:** اختبارات القاعدة في `uploadService/psqlDb/pgAuthStore/releaseOverview` تمرّ هنا باختبار **نائب لا يختبر شيئًا** لعدم وجود PostgreSQL؛ فالرقم لا يعني أن مسارات SQL اختُبرت.
- **أرشفة:** `unzip -t` يقرّ الأرشيف ويستخرج بايتات مطابقة؛ `python zipfile.testzip()` يقرأ الأسماء العربية UTF-8 ويتحقق CRC. هذان أداتان مستقلتان عن الكود.
- **دخول المعلمة:** يشمل كود/PIN/رمز، رفضًا موحّدًا (نفس الرمز والرسالة لكل الأسباب)، قفلًا وانفكاكه، عدم تمديد القفل أثناءه، تقييد العنوان، انتهاء مطلقًا وخمولًا، إبطال الجلسات عند إعادة الإصدار، عدم تسرب الكود/PIN/IP الخام إلى سجل المحاولات، وفحصًا فظًّا لتقريب الزمن.
- **اختبار الطفرات** (كسر الكود عمدًا): دخول المعلمة **10/10 أُمسكت**؛ الأرشفة **7 من 8**، والثامنة (إزالة رفض `..` صراحة) **مكافئة**: يرفضها فحص «مكوّن ينتهي بنقطة» الموجود أصلًا (دفاع مضاعف، لا ثغرة).
- **`tsc --strict --noUnusedLocals`** على 10 ملفات جديدة/معدّلة وما تستورده (يشمل `uploadService.ts`): نظيف. **تحفّظ:** شُغِّل بمترجم TypeScript 6.0.3 المحلي مع `@types/node` من حزمة أخرى وتعريف vitest مبسّط، **لا** بسلسلة المشروع (`npm run typecheck`). تأكدت أنه يلتقط خطأً مقصودًا.
- **فحصا SQL الساكنان:** 39/39 و30/30 (لم يتغير SQL الأصلي).
- **قياس:** PBKDF2-SHA256 بـ600,000 تكرار ≈ 104 مللي ثانية في Node هنا؛ **ليس** قياسًا لـEdge Functions ولا للخطة المجانية.
- **لم يُشغَّل إطلاقًا:** `vitest` الكامل، `npm run typecheck`، `npm run build`، `build:review`، اختبارات الواجهة، أي SQL، تزامن حقيقي لـ`recordFailure`، أي اتصال حقيقي، Windows.

## 4) حدود معروفة لما أُنجز
- **ZIP:** بلا ضغط وبلا ZIP64 (≤ 65,534 ملفًا و< 4 GiB)، في الذاكرة (لا بث). **لا يوجد بعد** مُجمِّع يقرأ الإصدارات من القاعدة والملفات من التخزين ويبني أرشيف معلمة/فصل. **مخطط المسارات داخل الأرشيف غير مقرَّر** (وهل تدخل أسماء المعلمات فيها؟).
- **دخول المعلمة:** لا دالة HTTP/Edge ولا ربط بشاشة الدخول الحالية (التي ما زالت تبحث عن الكود محليًا بحسب التصميم §1). `issueCredentials` لا تتحقق أن المتصل هي المالكة. لا توزيع للأكواد (OQ-09 معلّق).
- **`recordFailure` ذرّي بأمر SQL واحد** نظريًا؛ لم يُختبر تزامنه على قاعدة (الاختبار مكتوب في `pgAuthStore.test.ts`).
- **`overview`** لا تعتمد مواصفة سابقة (لا شيء بهذا الاسم في الحزمة سوى صفحات الواجهة)؛ اخترتُ: أعداد الجلسات بحسب الحالة + الجلسات المنتظرة (uploaded/validating) + ملخص التسليمات، **بلا مفاتيح تخزين ولا بصمات ولا روابط**.
