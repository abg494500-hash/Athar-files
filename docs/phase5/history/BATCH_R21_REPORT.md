# تقرير الدفعة (0.6.12، حزمة r21) — ربط الواجهات بالخادم، التدقيق الدائم، بيان الأرشيف، وتجهيز SQL للتنفيذ (A-103)

> **الحالة بصدق:** البيئة ما زالت بلا PostgreSQL ولا npm ولا شبكة (جُرّب فعليًا في بداية الدفعة: `npm view` لم يُرجع شيئًا ولا `psql` ولا `postgres`). لذلك **لم يُنفَّذ typecheck ولا vitest ولا build بأدوات المشروع، ولم يُشغَّل أي SQL على أي قاعدة، ولم يُجرَّب R2 ولا خادم منشور**. لم يُلمَس Supabase ولا Cloudflare ولا أي نشر، ولا أسرار في أي ملف. نسخة r20 الأصلية محفوظة دون تعديل في `previous-versions/`. المرفق في الرفع كان r18 فقط؛ بنيتُ على شجرة r20 التي سلّمتُها (مطابقة لمساحة الإخراج). **المنصة غير جاهزة للمدرسة ولا للنشر.**

## 2) الاختبارات: الحقيقي مقابل البديل
- **مشغّل Node البديل: 346/346** (318 + 28 جديدًا). **ليس vitest**.
- **`tsc --strict --noUnusedLocals` على ملفات الخادم الجديدة والعملاء:** نظيف (مترجم TypeScript 6.0.3 المحلي و`@types/node` من حزمة أخرى، **لا سلسلة المشروع**).
- **فحص نوعي مُقنَّن لصفحات React** (Portal, TeacherPortalContext, Login, App, TeacherDetail, VersionList, Archive, StaffApiContext): نظيف، لكن **بتعريفات بديلة** تجعل `react` و`react-router-dom` و`lucide-react` و`@supabase/supabase-js` بلا أنواع حقيقية (any)؛ يلتقط أخطاء الاستيراد والمتغيرات غير المستعملة وخصائص مكوّناتنا (أمسك كسرًا عمديًا لنغمة `Alert`؛ أما الخطأ الحقيقي `tone: 'success'` في `Portal.tsx` فالتقطتُه بقراءة الكود قبل تشغيل الفحص وصحّحتُه إلى `ok`) **ولا يلتقط أخطاء أنواع React نفسها** (hooks، الأحداث، JSX). هذا لا يغني عن `npm run typecheck`.
- **اختبار طفرات** على الكود الجديد: 9 كسرات عمدية؛ 8 أُمسكت من أول مرة، والتاسعة (مقارنة البصمة المحلية في تنزيل الأرشيف) لم تُمسك فشدّدتُ الاختبار وأُمسكت.
- **فحوص ساكنة:** SQL 39/39 و30/30 (قديمة) + **28/28 جديدة لـ006/007** + **فحص توافق عبارات SQL في الخادم مع مخطط 001–007 (أمسك 3/3 كسور عمدية)** — كلها نصية، **ليست دليلًا على نجاح SQL**.
- **لم يُشغَّل إطلاقًا:** vitest الكامل، `npm run typecheck`، `npm run build`، اختبارات الواجهة (`teacherPortal.test.tsx` الموسّع)، أي SQL (بما فيه `tests/sql/35_...`)، R2، أي خادم، Windows.

## 3) ما يحتاج تجربة فعلية قبل أي ثقة (بالأولوية)
1. `npm run typecheck` ثم `npm test` ثم `npm run build` على جهازكِ (صفحات React الأربع الجديدة/المعدّلة لم تُجمَّع قط؛ توقعي أخطاء).
2. تنفيذ SQL على قاعدة تجريبية بالترتيب (`docs/SUPABASE_SETUP_AR.md`)، وقبله اختياريًا اختبارات PostgreSQL المحلية (`tests/sql/run-sql-tests.ps1`) — **أول تشغيل لـ004 وlog_audit_as وحارس الأرشيف وكل SQL الخدمات**.
3. **فجوة تشغيلية كبرى لم أبنِها:** لا يوجد **مشغّل Db إنتاجي** (اتصال PostgreSQL من الخادم) ولا **مضيف** (Edge/Worker). `composeApi(env, db)` جاهز لكنه يحتاج كليهما. لذلك **لا دخول فعلي ولا رفع فعلي ممكن بعد** مهما نُفِّذ SQL.
4. تجربة R2 الفعلية بقائمتها (`R2_INTEGRATION_AR.md`)، وCORS.

## 4) ملفات SQL (مجهّزة، غير منفَّذة)
التسلسل: `001 → 002 → 003 → 004 → 005 → 006 → 007` (في `database/`) ومولَّداتها في `supabase/`: `01 → 01b → 02 → 03 → 01c → 03b`. الشرح الكامل بالعربية بخطوات التنفيذ ومعرفة النجاح والأخطاء: **`docs/SUPABASE_SETUP_AR.md`**؛ الجرد مقابل الكود: **`database/README_SEQUENCE_AR.md`**.
- **006:** `teacher_sessions` (RLS بلا policies) + فهرس فريد لبصمة الكود. (محتواه مطابق لمسودة 006 بعد مطابقته مع `pgAuthStore`؛ المسودة الأصلية باقية.)
- **007:** `log_audit_as` (أثر دائم بمنفِّذة موثّقة)، حارس `archives`، فهرس `versions(teacher_id, term_id)`. **لا جداول ولا أعمدة جديدة.**
- **ما لم يُضَف وسببه:** جدول تدقيق ثانٍ (يكفي `audit_log`)، `archive_entries`/`versions.archive_id` (مرتبطان بحذف نهائي غير مبني)، أي عمود لاسم الملف (موجود).
- اختبارات: `tests/sql/35_server_additions_006_007.sql` (محلي فقط، تشغّله `run-sql-tests.sh/.ps1` كتشغيل d)، و`supabase/03b_post_check_additions.sql` (قراءة فقط، 12 فحصًا) لـSupabase.
- قاعدة فارغة: الملفات 1 و2 و5 (والتحقق 4 و6). ما يحتاج قاعدة تجريبية: الملف 3 (يتراجع) واختبارات `tests/sql` (PostgreSQL محلي مؤقت لا Supabase).

## 5) قرارات حسمتُها بأمان (راجعيها)
- التدقيق الدائم عبر `log_audit_as` على `audit_log` الموجود (لا جدول جديد)، وفشله يمنع الإجراء الحساس.
- واجهات الإدارة والمعلمة تستعمل **المتغير نفسه** `VITE_TEACHER_API_URL` (اسمه تاريخي) ولا يُفعَّل أي سلوك جديد إن لم يُضبط؛ فالسلوك الحالي يبقى كما هو.
- الأرشفة عبر الخادم: فصل أو معلمة واحدة في فصل؛ **«سنة كاملة» غير مدعومة عبر الخادم بعد** (تُعطَّل في الواجهة).
- أحداث دخول المعلمة وتنزيلها **لا تُكتب** في `audit_log` (جداول التدقيق للموظفات؛ محاولات الدخول في `login_attempts`).
- مدد الروابط المؤقتة: رفع ≤ 15 د، ملف 60 ث، أرشيف 120 ث (افتراض).

## 6) قبل استخدام المنصة في المدرسة (لا يزال لازمًا)
تجميع واختبار الواجهة فعليًا؛ تنفيذ SQL وفحوصه على قاعدة تجريبية ثم تجارب حقيقية لكل مسار (الدخول، الرفع، الاستبدال، التنزيل، الأرشفة، الإفراج، الأثر الدائم)؛ بناء مشغّل Db ومضيف الخادم؛ ضبط R2 وCORS وتجربته؛ تأكيد القرارات المعلّقة (`HANDOFF.md`)؛ اختبار أمني واختبار حمل؛ وموافقتكِ الصريحة على كل إجراء حقيقي. **لا شيء من هذا تحقق بعد.**

## 7) ما يحتاج موافقتكِ الصريحة (لم أفعله)
تنفيذ أي SQL على Supabase (يدويًا بالخطوات أعلاه)، ضبط R2/CORS، نشر الخادم، إنشاء حسابات المسؤولين، وضبط `VITE_TEACHER_API_URL`.
