## تسلسل التحقق في الدخول
getUser من الخادم ← صف نشط في `staff_profiles` بدور owner|director (قبل أي TOTP) ← مستوى الضمان: aal2 أو طلب الرمز أو تسجيل عامل ← عند aal2 تأكيد الدور من الخادم بـ`current_staff_role()` ومطابقته للصف. أي خطأ أو تعارض ⇒ تسجيل خروج (فشل مغلق). رسالة واحدة لكلمة مرور خاطئة ولحساب غير مخوَّل. **هذا للتجربة فقط؛ الحماية الحقيقية للبيانات في RLS.**

## مخاطر ومشكلات معروفة
1. **ملفات React والاختبارات الجديدة لم تُترجَم ولم تُنفَّذ**: قد تظهر أخطاء أنواع/اختبارات عند أول تشغيل عندكِ. أصلحها بعد إرسال النص.
2. **`package-lock.json` لم يُحدَّث** (انظر `docs/ENV_LOCAL_AR.md`: `npm install` أولًا).
3. **الكتابات المباشرة غير مسجَّلة في سجل العمليات** (إضافة سنة/معلمة، تفعيل سنة): تُعالج في المرحلة 6 بدوال خادمية بقرار صاحبة المشروع.

5. **الفصل «الحالي» مشتق** من المواعيد (A-84)، لا مخزَّن.
6. **سجل العمليات يعرض آخر 500 قيد**؛ الصفحات الأقدم لاحقًا. وللمديرة فارغ (A-46).
7. aal2 على JWT حقيقي ورفض بريد غير مسجَّل **لم يُختبرا على مشروعكِ بعد**.
8. فحص `dist` (لا بيانات وهمية) يتطلب `npm run build` ثم `node scripts/check-dist-no-mock.mjs` عندكِ.

9. **ملف المعاينة القديم** نُقل إلى `review/archive/athar-ui-review.v0.5.4.html` لأنه مبني من 0.5.4 ويحوي الدخول الوهمي؛ يُعاد توليد `review/athar-ui-review.html` بـ`npm run build:review` (لم يُشغَّل هنا).
