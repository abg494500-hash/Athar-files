# ملف التسليم — ما أُنجز في الكود وما تبقى عليكِ يدويًا (r26 / 0.6.17)

> **صدق أولًا:** لا شيء من «الخدمات الحقيقية» جُرِّب بعد. الاختبارات التي نجحت فعلًا عندكِ على Windows: `typecheck` و`npm test` (476) و`npm run build` — وكلها على **بدائل** (قاعدة وهمية، npm مزيَّف، fetch وهمي، R2 وهمي). **المنصة غير جاهزة للمدرسة ولا للنشر.** ولم تُعالَج ثغرات npm التسع بعد (انظر §E).

## أ) ما أُنجز داخل الكود (وكيف اختُبر)
| المجال | ما أُنجز | الاختبار الفعلي |
|---|---|---|
| دخول المعلمة | كود + رقم سري (PBKDF2)، قفل بالحساب والعنوان، جلسات برمز معتم، فشل موحّد | اختبارات منطق + محاكاة (لم تمسّ قاعدة حقيقية) |
| صلاحيات الخادم | مالكة/مديرة/معلمة في كل مسار؛ التحقق من JWT المسؤولة عند Supabase Auth ثم دور `staff_profiles` | اختبارات بدائل |
| التدقيق | أثر دائم لمن نفّذ الإفراج (داخل معاملته) وتدقيق قبل كل إجراء حساس بفشل مغلق (`log_audit_as`) | بدائل؛ SQL لم يُشغَّل |
| الرفع/الاستبدال/الرابط | start ← رابط PUT موقّع ← رفع مباشر ← إتمام يقيس الخادم الملف (حجم/توقيع/بصمة) ← نسخة جديدة؛ مواعيد **مستقلة لكل فصل** | بدائل؛ لا R2 حقيقي |
| التنزيل | معلمة (ملفاتها) ومالكة/مديرة (أي ملف) برابط موقّع 60 ث | بدائل |
| الأرشفة | بناء ZIP من الملفات الفعلية بفشل مغلق عند أي تلف، إعادة قراءة من التخزين، `archive_entries` غير مملوءة، بيان بـ`original_name`، تأكيد بصمة التنزيل | بدائل + فحص مستقل لـZIP |
| مشغّل القاعدة والمضيف | `postgres.js` + دالة Edge `api` (Deno) + بناء متوافق | بدائل ومحاكاة؛ **لم يُشغَّل في Deno** |
| الواجهة | بوابة المعلمة، تنزيل المديرة/المالكة، الأرشيف، إصدار الأكواد، عمليات الرفع والإفراج (تظهر **فقط** عند ضبط `VITE_TEACHER_API_URL`) | `typecheck` و`npm test` و`build` ✅ عندكِ؛ لم تُجرَّب مع خادم |
| الحمايات | فحص عدم تسرب الأسرار للواجهة، حارس السياسة للاعتماديات، فحوص SQL الساكنة | ✅ |

## ب) ما لم يُنفَّذ إطلاقًا (لا تفترضي نجاحه)
أي SQL على أي قاعدة (001–007)، دالة Edge في Deno، `postgres.js` الحقيقي، R2 (رفع/تنزيل/CORS/`If-None-Match`/توقيع `content-length`)، دخول حقيقي، أي تجربة نهاية-إلى-نهاية، اختبار حمل/أمن، وإصلاح ثغرات npm.

> **الدليل الموحَّد بالتفصيل (أوامر PowerShell وفتح الحسابات): `docs/DEPLOYMENT_GUIDE_AR.md`.** ما يلي ملخص منه.

## ج) الخطوات اليدوية عليكِ، بالترتيب
**0. الآن (يسبق كل شيء): الثغرات** — `WINDOWS_BATCH_R26_AR.md` (ملف مستقل بلا فك أرشيف) ثم دفعات `NPM_FULL_PLAN_AR.md`، وأرسلي نتيجة كل بوابة (`typecheck`/`test`/`build`/`audit`).
**1. SQL على مشروع Supabase تجريبي جديد وفارغ** (بلا بيانات حقيقية) — حرفيًا `docs/SUPABASE_SETUP_AR.md`: الملفات بالترتيب `01_apply_all` ← `01b_staff_accounts` ← `02_security_check` ← `03_post_check` ← `01c_server_additions` ← `03b_post_check_additions`، ولكل ملف معيار نجاحه وجدول أخطائه. **أرسلي لي أي رسالة خطأ كما هي؛ متوقع أخطاء عند أول تنفيذ (004 و`log_audit_as` وحارس الأرشيف).** لا تنفّذيها على مشروع فيه بيانات حقيقية.
**2. حسابات المسؤولين:** Authentication ← Users ← Add user (بريد وكلمة مرور قوية فريدة لكل حساب)، ثم في SQL Editor: `select public.bootstrap_staff('بريد-المالكة', 'owner');` و`... 'director'` للمديرة.
**3. Cloudflare R2:** حاوية **خاصة**، مفتاح API بصلاحية Object Read & Write على هذه الحاوية فقط، وCORS: الأصل = أصل موقعكِ فقط؛ `PUT` (ترويسات `content-length`, `content-type`) و`GET` (لتنزيل الأرشيف بـfetch) — `docs/phase5/R2_INTEGRATION_AR.md` (ومعه قائمة التجارب الثمانية).
**4. أسرار الدالة** (`supabase secrets set`، القيم من مدير كلمات المرور، **لا في أي ملف ولا محادثة**): `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `TEACHER_CODE_PEPPER`, `TEACHER_PIN_PEPPER`, `TEACHER_IP_PEPPER` (كلٌّ ≥ 32 محرفًا عشوائيًا ومختلف)، `ALLOWED_ORIGIN` (أصل موقعكِ بـhttps بلا مسار). يوفّر Supabase تلقائيًا `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_DB_URL`. **لا تستعملي مفتاح الخدمة (`service_role` key) في أي مكان.**
**5. نشر الدالة:** `supabase functions deploy api --no-verify-jwt` ثم `GET .../functions/v1/api/health` ⇒ `{"ok":true}` — خطوات التراجع والمخاطر في `docs/phase5/EDGE_HOST_AR.md` (أول تشغيل في Deno: توقعي أخطاء توافق).
**6. الواجهة:** `.env.local` بـ`VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` و`VITE_TEACHER_API_URL=https://<المشروع>.supabase.co/functions/v1/api` (كلها عامة)، ثم `npm run build` و`node scripts/check-no-secrets-in-frontend.mjs` (10/10) و`node scripts/check-dist-no-mock.mjs`، ثم استضافة ملفات `dist` (منصة الاستضافة لم تُحسَم).
**7. تجارب نهاية-إلى-نهاية** (حسابات تجريبية): مالكة تدخل ← تصدر كودًا لمعلمة ← المعلمة تدخل ← ترفع ملفًا صغيرًا ← تستبدله ← تحفظ رابطًا ← تنزّله ← المديرة تنزّل ملفها ← المالكة تنشئ أرشيفًا وتنزّله وتتحقق من بصمته ← إفراج عن جلسة عالقة (يُسجَّل باسم المنفِّذة في «سجل العمليات») ← اختبار رفض: معلمة تطلب ملف معلمة أخرى، مديرة تحاول إنشاء أرشيف، دخول بكود خاطئ مرارًا (قفل)، رفع بعد موعد الفصل مع بقاء فصل آخر مفتوحًا.

## د) قرارات تنتظركِ
افتراض الرفع المباشر بـPUT موقّع ومدد الروابط (رفع ≤ 15 د، ملف 60 ث، أرشيف 120 ث)؛ حدود 30MB للكائن و40MB للأرشيف (الأرشفة بالذاكرة)؛ منصة استضافة الواجهة؛ جدولة تنظيف الجلسات المنقضية (حاليًا زر يدوي للمالكة)؛ أرشفة سنة كاملة عبر الخادم؛ تدقيق دائم لأحداث المعلمة؛ الحذف النهائي و`archive_entries`؛ قرارات §9 القديمة في `HANDOFF.md`.
