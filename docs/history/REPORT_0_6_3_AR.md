## 3) مراجعة تكرار طلب التحقق بخطوتين
لم أستطع إعادة إنتاج المشكلة على Supabase حقيقي (ممنوع الاتصال بها). بالقراءة والاختبار بعميل وهمي وجدتُ:
1. **(مرجّح ومثبت من الكود والتوثيق)** `auth.signOut()` بلا معاملات في supabase-js نطاقه الافتراضي `global`: يبطل جلسات **كل الأجهزة**. أي خروج (زر الخروج، «إلغاء وتسجيل الخروج»، أو رفض) على الهاتف يُسقط جلسة الحاسوب فيُطلب كلمة مرور + TOTP من جديد.
2. **(مثبت بالاختبار)** `deny()` كانت تمحو الجلسة عند أي خطأ أثناء التحقق، حتى لو مؤقتًا (503/429/انقطاع). فجلسة aal2 سليمة تضيع بسبب لحظة سيئة في الشبكة.
3. **(بيئي، لا يُصلح بالكود)** الجلسة تُخزَّن لكل «أصل» (origin): `localhost:5173` غير `127.0.0.1:5173` غير `localhost:4173`؛ والتصفح الخاص أو مسح بيانات الموقع عند الإغلاق يمحوها.
**ما نُفّذ (A-93):** الخروج والرفض بنطاق `local`؛ العطل المؤقت (شبكة/5xx/429/408) ⇒ حالة `check_failed` بلا دخول وبلا محو للجلسة + زر «إعادة المحاولة» (ويعاد تلقائيًا عند عودة الإنترنت) يعيد التقييم الكامل؛ الجلسة الباطلة فعلًا (401/403) تُمحى محليًا.
**لم يتغير:** TOTP إلزامي؛ `authorized` لا يتحقق إلا عند aal2 + تأكيد الدور من الخادم؛ الرفض القاطع (غير مخوَّلة، تعارض دور، خطأ قاعدة غير مؤقت) كما كان؛ RLS؛ aal1 لا يُظهر أي بيانات (مُختبر).
**ما يحتاج موافقتكِ (لم يُنفَّذ):** (أ) زر «الخروج من كل الأجهزة» (الدالة جاهزة `signOut('global')` دون واجهة)؛ (ب) أي مدة جلسة/خمول في لوحة Supabase (بعضها Pro فقط)؛ (ج) «تذكّر هذا الجهاز» لتخطي TOTP — **لا أنصح به**.
**تغيير يستحق مراجعتكِ:** نطاق الخروج الافتراضي صار محليًا. تراجعين عنه بتغيير `scope = 'local'` إلى `'global'` في `controller.ts` (دالتا `quietSignOut` و`signOut`)؛ وفحص `check-stage3-static.mjs` سيُنبّه لذلك.

## 7) خطوات التشغيل لمبتدئة على Windows
**أ) فك الحزمة:** انسخي `athar-handoff-stage3-wip-redesign-v0_6_3-r12.zip` إلى `C:\athar-test` (أنشئي المجلد إن لم يوجد) ← كليك يمين ← **Extract All** ← Extract. يظهر المشروع في `C:\athar-test\athar-handoff-...-r12\athar` (أو `C:\athar-test\athar`). ادخلي مجلد `athar` الذي فيه `package.json`.
**ب) فتح PowerShell هناك:** في شريط عنوان المستكشف (أعلى النافذة) اكتبي `powershell` ثم Enter. تظهر نافذة زرقاء/سوداء ويكون المسار ينتهي بـ`\athar`.
**ج) أول مرة فقط:** اكتبي `npm install` ثم Enter (يحتاج إنترنت، دقائق). **اشتغل إن:** انتهى بسطر «added … packages» دون كلمة ERR. إن ظهر «running scripts is disabled» استعملي `npm.cmd install`.
**د) معاينة التصميم (بلا Supabase):** اكتبي `npm run build:review` ثم Enter. **اشتغل إن:** ظهر «تم: …athar-ui-review.html». افتحي الملف `review\athar-ui-review.html` بالنقر المزدوج. اضغطي زر «عرض الواجهات» (أسفل يسار الصفحة) ← «المالكة» أو «المديرة» لرؤية الصفحة الرئيسية بالبطاقات.
**هـ) تجربة الحاسوب والهاتف:** على الحاسوب اضغطي F12 ثم رمز الجوال (Toggle device toolbar) واختاري iPhone أو Pixel لرؤية العرض الضيق. على هاتف حقيقي: شغّلي `npm run dev -- --host` وافتحي في الهاتف العنوان الذي يظهر باسم Network (مثل `http://192.168.x.x:5173`) على نفس شبكة الواي فاي؛ وسترين رسالة «الاتصال غير مُعدّ» حتى تُنشأ `.env.local` (راجعي `docs/ENV_LOCAL_AR.md`) — وهذا سلوك صحيح.
**و) الدخول الحقيقي (فقط بعد إعداد `.env.local` وبموافقتكِ على المرحلة):** `npm run dev` ثم افتحي `http://localhost:5173/` **دائمًا بالعنوان نفسه** (لا تبدّلي بين localhost و127.0.0.1) كي لا تضيع الجلسة. **اختبار الجلسة:** سجّلي الدخول + TOTP مرة، ثم حدّثي الصفحة F5: **المتوقع** أن تبقي داخل الصفحة الرئيسية بلا طلب رمز جديد. إن ظهر «تعذّر التحقق من الجلسة مؤقتًا» فاضغطي «إعادة المحاولة».
**ز) إيقاف الخادم:** في نافذة PowerShell اضغطي `Ctrl+C` ثم `Y` ثم Enter، ثم أغلقي النافذة.
**ح) الفحوص (اختياري، أرسلي النتائج كما هي):** `npm run typecheck` ثم `npm test` ثم `npm run build`. المتوقع: بلا أخطاء، و«Tests 207 passed».
**ط) عند الخطأ:** لا تحاولي الإصلاح؛ انسخي النص الأحمر كاملًا وأرسليه. **لا ترسلي كلمات مرور ولا مفاتيح.**
