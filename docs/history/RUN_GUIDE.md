# دليل تشغيل نموذج «أثَر» على Windows (للمبتدئة) — محدّث بعد المرحلة 4.4

> **تنبيه مهم:** ما تشغّلينه هنا **واجهات ببيانات توضيحية فقط**. لا اتصال بأي خدمة ولا خادم ولا قاعدة بيانات.
> كل ما تُدخلينه أو تعدّلينه يبقى **في ذاكرة الصفحة المفتوحة فقط، وليس تخزينًا دائمًا**: عند **تحديث الصفحة (F5) أو إغلاقها** تضيع التعديلات وتعود البيانات لأصلها. هذا سلوك متوقع، وتظهر للمستخدمة رسالة تقول ذلك في أعلى الصفحات وفي شاشة الدخول.
> لا تُدخلي بيانات حقيقية (أسماء معلمات حقيقية أو ملفات حقيقية) في هذا النموذج.

---

## الطريقة 1 — الأسهل: فتح ملف المراجعة (دون تثبيت أي برنامج)

**ما تحتاجينه:** متصفح (Chrome أو Edge أو Firefox أو Safari). لا شيء آخر.

1. فُكّي ضغط الملف `athar-handoff-phase5-1b-v0.5.2.zip`: اضغطي عليه بالزر الأيمن ← **Extract All…** (استخراج الكل) ← **Extract**. سيظهر مجلد جديد بالاسم نفسه.
2. افتحي المجلد، ثم افتحي المجلد الفرعي **`review`**.
3. اضغطي مرتين على الملف **`athar-ui-review.html`**. يفتح في المتصفح.
4. **كيف أعرف أنه اشتغل؟** تظهر صفحة «تسجيل الدخول» بشعار أثَر على خلفية خضراء (على الكمبيوتر)، وتحت بطاقة الدخول مستطيل أزرق فاتح مكتوب فيه «البيانات المعروضة مؤقتة…»، وفي أسفل-يسار الشاشة زر **«عرض الواجهات»**.
5. اضغطي «عرض الواجهات» لتنتقلي بين واجهات المعلمة والمديرة والمالكة، وتغيّري حالة المعلمة والتاريخ المعروض وحالة الصفحة (تحميل/خطأ/لا بيانات).
6. **اختبار الهاتف:** أرسلي الملف `athar-ui-review.html` لنفسك (واتساب أو بريد) وافتحيه من الهاتف، **أو** على الكمبيوتر اضغطي F12 ثم Ctrl+Shift+M (وضع الهاتف في Chrome/Edge) لرؤية تخطيط الهاتف.
7. **اختبار الكمبيوتر:** افتحي الملف في نافذة كبيرة عادية.
8. **لإيقافه:** أغلقي تبويب المتصفح. لا يوجد خادم يعمل في هذه الطريقة.

## الطريقة 2 — تشغيل المشروع كاملًا للتطوير والاختبار

### أ) ما تحتاجين تثبيته مرة واحدة
1. **Node.js** الإصدار 20 أو أحدث: ادخلي إلى nodejs.org وحمّلي نسخة **LTS**، وثبّتيها بالضغط على Next حتى النهاية، ثم **أعيدي تشغيل الكمبيوتر**. **للتأكد:** في الطرفية اكتبي `node -v` ← يجب أن يظهر رقم يبدأ بـ v20 أو أعلى (مثل v22.11.0).
2. **VS Code** (محرر نصوص): من code.visualstudio.com.

### ب) فتح المشروع
1. فُكّي ضغط الملف كما في الطريقة 1 (ضعي المجلد في مكان سهل مثل `C:\athar-app` أو سطح المكتب).
2. افتحي **VS Code** ← القائمة **File** ← **Open Folder…** ← اختاري **المجلد الذي فيه الملف `package.json`** (وليس مجلدًا داخله).
3. افتحي الطرفية: القائمة **Terminal** ← **New Terminal**. يظهر شريط في أسفل VS Code فيه مؤشر الكتابة.

### ج) التثبيت (مرة واحدة فقط)
- اكتبي في الطرفية ثم اضغطي **Enter**: `npm install`
- انتظري دقيقة أو دقيقتين. **علامة النجاح:** تظهر عبارة مثل «added 231 packages» ثم يعود المؤشر. قد تظهر تحذيرات صفراء `npm warn` وهي عادية.

### د) تشغيل النموذج للتجربة الحية
1. اكتبي: `npm run dev` ثم Enter.
2. **علامة النجاح:** يظهر سطر فيه `Local: http://localhost:5173/`.
3. اضغطي Ctrl مع الضغط على ذلك العنوان (أو انسخيه إلى المتصفح). تظهر صفحة «تسجيل الدخول».
4. **للدخول كمعلمة:** اكتبي الرمز `ABCD2345XY` (في النموذج يُقبل أي رمز من 8 خانات أو أكثر حروفًا إنجليزية وأرقامًا) ← متابعة ← «نعم، هذه أنا». **للدخول كمالكة أو مديرة:** تبويب «الإدارة»، اكتبي أي بريد صحيح الشكل (مثل `owner@example.com`؛ ما يبدأ بـ`director` يدخل كمديرة) وأي كلمة مرور.
5. **كيف أعرف أن «التسليم» يعمل؟** سجّلي دخول معلمة ← اضغطي «تسليم» ← تبويب «رابط خارجي» ← اكتبي `https://example.org/a` ← تسليم. يظهر «تم تسجيل التسليم» ويتغير سجل النسخ. **ثم اضغطي F5: يعود كل شيء لأصله** وتعودين إلى شاشة الدخول — وهذا هو المقصود بأن التخزين مؤقت.
6. **اختبار الهاتف على شبكة بيتك (اختياري):** أوقفي الخادم، ثم شغّلي `npm run dev -- --host`. سيظهر عنوان `Network:` مثل `http://192.168.1.5:5173/`؛ افتحيه من هاتفك المتصل بالشبكة نفسها.
7. **اختبار الكمبيوتر:** الخطوة 3 نفسها.
8. **لإيقاف الخادم:** اضغطي **Ctrl + C** في الطرفية (قد يسأل «Terminate batch job؟» اكتبي Y ثم Enter).

### هـ) الاختبارات الآلية وفحص الأنواع والبناء
1. اختبارات: `npm test`
   - **علامة النجاح:** «Tests 100 passed (100)» و«Test Files 6 passed (6)». تحقق من هذا الرقم فعليًا في 2026-10-20 (بعد 5.1ب) على Linux (Node 22) ولم يُجرَّب على Windows بعد، فإن ظهر عندك رقم مختلف أو كلمة failed أرسليها لي كما هي. قد تظهر تحذيرات «React Router Future Flag Warning» وهي عادية.
2. فحص الأنواع: `npm run typecheck` ← **النجاح:** لا يطبع أخطاء ويعود المؤشر.
3. **البناء النهائي بلا شريط المراجعة:** `npm run build` ← الناتج في المجلد `dist`.
4. **إعادة بناء ملف المراجعة** (إن غيّرتِ شيئًا): `npm run build:review` ← **النجاح:** آخر سطر «تم: …\review\athar-ui-review.html (… KB). مجلد dist لم يُمسّ.» ويُحدَّث الملف مباشرة، ولا حاجة لنسخ شيء يدويًا ولا يتأثر مجلد `dist`.

## ماذا أفعل عند خطأ؟
| ما يظهر | ما تفعلينه |
|---|---|
| «npm غير معروف» / `'npm' is not recognized` | ثبّتي Node.js ثم **أغلقي VS Code وافتحيه من جديد** (وأحيانًا أعيدي تشغيل الجهاز) |
| «المنفذ مستخدم» / `Port 5173 is in use` | أغلقي الطرفية القديمة بـCtrl + C، أو أغلقي VS Code وافتحيه، أو أعيدي تشغيل الجهاز |
| صفحة بيضاء | اضغطي F12 ← تبويب **Console** ← صوّري الخطأ الأحمر وأرسليه لي |
| فشل `npm install` | تأكدي من الاتصال بالإنترنت ثم أعيدي الأمر؛ إن تكرر أرسلي آخر 20 سطرًا من الطرفية |
| `Cannot find package.json` | أنتِ في مجلد خاطئ: افتحي في VS Code المجلد الذي يحوي الملف `package.json` مباشرة |
| في PowerShell: «npm.ps1 cannot be loaded because running scripts is disabled» | اكتبي مرة واحدة: `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` ثم Enter ثم اكتبي Y، وأعيدي الأمر. **أو** افتحي طرفية من نوع **Command Prompt** (في VS Code: السهم بجانب + ← Command Prompt) بدل PowerShell |
| تظهر نافذة «Windows Defender Firewall» عند `npm run dev -- --host` | اضغطي «Allow access» للشبكات الخاصة إن أردتِ فتحه من الهاتف، وإلا اضغطي Cancel واستعملي الكمبيوتر فقط |
| `node -v` يعرض رقمًا أقل من 20 | ثبّتي Node.js LTS الأحدث ثم أعيدي تشغيل الجهاز |
| فشل في `npm test` | أرسلي لي النص الظاهر كما هو، ولا تعدّلي شيئًا |
| تضيع بياناتي بعد F5 | هذا متوقع: التخزين مؤقت (انظر التنبيه في أول الدليل) |

## تجربة حد حجم الملف محليًا
الحد الافتراضي المؤقت 50 ميغابايت (غير نهائي). لتجربة رفض ملف كبير دون ملف ضخم:
1. في VS Code: على يسار الشاشة (مستكشف الملفات) اضغطي أيقونة «New File» وسمّيه بالضبط `.env.local` (بنقطة في أوله، وبلا امتداد `.txt`). **تجنبي** إنشاءه بالنوتباد لأن Windows قد يضيف `.txt` تلقائيًا.
2. اكتبي فيه سطرًا واحدًا: `VITE_ATHAR_MAX_FILE_BYTES=1000000` (مليون بايت ≈ 1 ميغابايت).
3. أوقفي الخادم (Ctrl + C) ثم شغّليه من جديد: `npm run dev`.
4. سجّلي دخول معلمة ← «تسليم» ← اختاري ملفًا أكبر من 1 ميغابايت ← تظهر رسالة «حجم الملف أكبر من الحد المسموح (1 ميغابايت)».
5. احذفي السطر أو الملف لتعودي للحد الافتراضي.
**ملاحظة صريحة:** الملف المرفوع يُحفظ في **تخزين وهمي داخل الصفحة** ويضيع عند تحديثها؛ لا شيء يُرسَل لأي خدمة، ورفع الملفات لخدمة حقيقية لم يُربط ولم يُختبر.

## للمطوّر: كيف تُستبدل طبقة البيانات لاحقًا (4.3)
- الصفحات تقرأ من `useStore()` فقط؛ المصدر يُحقن في `src/App.tsx` من `src/data/provider.ts`.
- اليوم: `createMockRepository()` (بيانات وهمية في الذاكرة، `persistent: false`).
- أي مصدر جديد يُنفِّذ `DataRepository` (`src/data/repository.ts`) ويجب أن يمرّ باختبارات العقد `src/test/repository.contract.ts`. **لا يُنفَّذ ذلك دون موافقتك الصريحة.**

## ما لا تفعليه الآن
- مجلد `database/` يحوي ملفات SQL **غير مجرَّبة**؛ لا تنفّذيها في Supabase ولا في أي مكان قبل أن نتفق على ذلك صراحةً.
- لا تنشئي حسابات خدمات ولا تضعي بطاقة ولا بيانات حقيقية.
- لا تشغّلي أي اختبارات V-01…V-10 (غير موجودة في النموذج ولا تُنفَّذ بلا إذنك).
