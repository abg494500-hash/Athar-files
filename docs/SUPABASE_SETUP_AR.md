# إعداد قاعدة Supabase لأثَر وتنفيذ ملفات SQL بالترتيب (r21 / 0.6.12)

> **حالة صادقة (اقرئيها أولًا):** كل ملفات SQL هنا **لم تُشغَّل على أي PostgreSQL ولا على Supabase** (بيئة كتابتها بلا PostgreSQL). فُحصت **نصيًا** فقط (فحوص ساكنة) وطُوبقت أعمدتها مع كود الخادم آليًا، وكُتبت لها اختبارات محلية لم تُنفَّذ. تنفيذها عليكِ هو **أول اختبار حقيقي لها**؛ لذلك: مشروع تجريبي فقط، بلا بيانات حقيقية، وأي رسالة خطأ تُرسَل لي كما هي. **لا ترسلي كلمات مرور ولا مفاتيح في المحادثة.** لا يُنفَّذ شيء من هذا على Supabase قبل موافقتكِ.

## 1) التسلسل النهائي (نفّذي بالترتيب، كل ملف في «New query» مستقل)

| # | الملف (في مجلد supabase) | مصدره | يعتمد على | يغيّر القاعدة؟ | ما يفعله |
|---|---|---|---|---|---|
| 1 | `01_apply_all.sql` | database/001–004 | مشروع **فارغ** | نعم، مرة واحدة | الجداول والحمايات والصلاحيات وسلسلة التدقيق وجداول الرفع |
| 2 | `01b_staff_accounts.sql` | database/005 | 1 | نعم (يمكن إعادته) | حسابات المسؤولين وحمايتها وإنشاؤها عبر `bootstrap_staff` |
| 3 | `02_security_check.sql` | اختبار الصلاحيات | 1 و2 | **لا** (يتراجع دائمًا ويعطي مربعًا أحمر مقصودًا) | يثبت أن anon/authenticated لا يتجاوزان الحدود |
| 4 | `03_post_check.sql` | قراءة فقط | 3 | لا | يثبت أن 3 لم يترك أثرًا (8 صفوف PASS) |
| 5 | `01c_server_additions.sql` | database/006 + 007 | 1 و2 (وبعد نجاح 3 و4) | نعم، معاملة واحدة، يمكن إعادته | جلسات المعلمات + فهرس بصمة الكود + `log_audit_as` + حارس الأرشيف + فهرس |
| 6 | `03b_post_check_additions.sql` | قراءة فقط | 5 | لا | 12 فحصًا لصلاحيات ما أضافه 5 (كلها PASS) |
| 7 | `01d_teacher_removal.sql` | database/008 | 1 و2 و5 | نعم، يمكن إعادته | عمود `removed_at` ودالة `remove_teacher` (حذف المعلمة بعد أرشفة كل تسليماتها) |
| 8 | `03c_post_check_removal.sql` | قراءة فقط | 7 | لا | 3 فحوص (كلها PASS) |

لماذا 5 بعد 3 و4؟ كي تُختبر الصلاحيات الأصلية على حالتها الأصلية أولًا، ثم تُضاف الإضافات وتُفحص بفحصها الخاص. **لا تنفّذي 5 قبل 1 و2** (يعتمد على `audit_log` وسلسلته وعلى `staff_profiles` و`archives` و`teachers`).

### ما الذي يغيّره 01c بالضبط (للمراجعة قبل الموافقة)
- **جدول جديد واحد:** `teacher_sessions` (جلسات دخول المعلمات؛ تُخزَّن بصمة الرمز لا الرمز). RLS مفعّلة بلا أي policy وكل الصلاحيات مسحوبة من الأدوار العامة ⇒ الخادم وحده يصل إليه.
- **فهرس فريد جديد:** على `teacher_credentials.code_hash` (جزئي: غير الفارغ).
- **دالة جديدة `log_audit_as`:** تكتب في سجل التدقيق **من نفّذ** الإجراء (إفراج جلسة، تنزيل ملف، إنشاء/تنزيل أرشيف، إصدار/إلغاء كود معلمة). تتحقق أن المنفِّذة موظفة نشطة وتأخذ دورها من `staff_profiles` (لا يقبل دورًا من المستدعي). التنفيذ لخدمة الخادم (`service_role`) وحدها. **سبب وجودها:** الدالة الأصلية `log_audit` تعتمد `auth.uid()` الفارغ عند اتصال الخادم بمفتاح الخدمة فتنسب الحدث إلى «النظام».
- **مشغّل جديد على `archives`:** لا يتراجع الأرشيف (creating ← awaiting_verification ← verified أو failed نهائي)، وبصمته وحجمه ومفتاحه وطوابع التنزيل والإقرار تُكتب مرة واحدة.
- **فهرس جديد:** `versions(teacher_id, term_id)` لقراءة بوابة المعلمة.
- **لا يغيّر ولا يحذف** أي جدول أو عمود أو قيد أو policy قائم. لا `drop` ولا `delete` ولا `update` على بيانات.
- **ما لم يُضَف عمدًا:** جدول تدقيق ثانٍ (يُستعمل `audit_log` الموجود)، `archive_entries` وعمود `versions.archive_id` (لا يُملآن قبل بناء مسار الحذف النهائي)، عمود لاسم الملف الأصلي (العمود `versions.original_name` موجود)، أي تغيير للتخزين (R2 خارج PostgreSQL).

## 2) ما يحتاج قاعدة تجريبية وما يُنفَّذ على قاعدة فارغة
- **قاعدة جديدة فارغة (مشروع Supabase تجريبي جديد):** الملفات 1 ثم 2 ثم 5. هذا هو المسار الموصى به.
- **اختبارات تُنفَّذ (تنشئ بيانات وتتراجع):** 3 على Supabase (آمنة: تتراجع دائمًا)؛ و`tests/sql/*.sql` (ومنها `35_server_additions_006_007.sql`) **على PostgreSQL محلي مؤقت فقط**، لا على Supabase، عبر `tests/sql/run-sql-tests.ps1` (انظر `docs/phase5/WINDOWS_RUN_GUIDE.md`).
- **فحوص قراءة فقط (على أي قاعدة):** 4 و6.
- **مشروع Supabase فيه بيانات حقيقية:** لا تنفّذي أي ملف قبل أن نتفق على نسخة احتياطية وخطة ترحيل. الملف 1 يرفض التنفيذ فوق جداول موجودة.

## 3) هل نفّذتِ شيئًا من قبل؟ (فحص قراءة فقط)
الصقي في New query وشغّلي، وأرسلي لي النتيجة:
```
select to_regclass('public.upload_sessions') is not null as ملف_1_منفَّذ,
       to_regprocedure('public.bootstrap_staff(text,text)') is not null as ملف_2_منفَّذ,
       to_regclass('public.teacher_sessions') is not null as ملف_5_منفَّذ;
```
`true` يعني منفَّذًا. لا تعيدي تنفيذ 1 إن كانت `true`.

## 4) الخطوات
1. **المشروع** (مرة واحدة، بيدكِ): supabase.com ← New project، الاسم `athar-test`، خطة Free، أقرب منطقة، كلمة مرور قاعدة بيانات قوية تحفظينها في مدير كلمات مرور (لا ترسليها). عطّلي التسجيل الذاتي (Authentication ← إعدادات تسجيل الدخول) واتركي الدخول المجهول معطّلًا. *أسماء الخيارات قد تختلف؛ أرسلي لقطة وسأدلّكِ.*
2. **ملف 1:** SQL Editor ← New query ← الصقي كل `supabase/01_apply_all.sql` ← Run.
3. **ملف 2:** query جديدة ← `01b_staff_accounts.sql` ← Run.
4. **ملف 3:** `02_security_check.sql` ← Run (وافقي على تحذير «destructive» إن ظهر).
5. **ملف 4:** `03_post_check.sql` ← Run.
6. **ملف 5:** `01c_server_additions.sql` ← Run.
7. **ملف 6:** `03b_post_check_additions.sql` ← Run.
8. **ملف 7:** `01d_teacher_removal.sql` ← Run، ثم **ملف 8:** `03c_post_check_removal.sql` ← Run (3 صفوف PASS).
8. **حسابات المسؤولين (بعد نجاح 1–6):** Authentication ← Users ← Add user (بريد وكلمة مرور قوية فريدة لكل حساب)، ثم في SQL Editor: `select public.bootstrap_staff('بريد-المالكة@...', 'owner');` ثم للمديرة `'director'`. (الدالة لا تعمل إلا من SQL Editor بصلاحية مالك القاعدة.)

9. **دالة الخادم (بعد نجاح 1–8 وبعد قراءة `docs/phase5/EDGE_HOST_AR.md`):** تُنشر دالة Edge باسم `api` بخطوات ذلك الملف. بدونها لا دخول معلمات ولا رفع ولا أرشفة (الواجهة تبقى «غير متاح»). لا تنفّذي النشر قبل موافقتي.

## 5) كيف أعرف أن كل خطوة نجحت؟
| الخطوة | النجاح يبدو هكذا | إن لم يكن كذلك |
|---|---|---|
| 1 و2 و5 | رسالة **Success** (قد يظهر تنبيه «transaction already in progress» وهو غير ضار) | انسخي الخطأ كما هو وأرسليه. معاملة الملف 2 و5 تُلغى كلها عند الخطأ فلا تترك نصف تطبيق؛ أما الملف 1 فقد يترك مشروعًا نصف مطبَّق ← نحذف المشروع التجريبي وننشئ غيره فارغًا |
| 3 | مربع **أحمر** يبدأ بـ`RESULT: PASS=… FAIL=0` (الأحمر مقصود) | `FAIL` أكبر من 0 أو `ABORT:` ← أرسلي النص كاملًا ولا تكرّري |
| 4 | 8 صفوف كلها PASS | أي FAIL ← أرسليه ولا تكملي |
| 6 | 12 صفًّا كلها PASS | أي FAIL ← أرسلي الصف (رقمه واسمه) ولا تكملي |
| 8 | `bootstrap_staff` يعيد بلا خطأ | انظر الجدول التالي |

## 6) أخطاء متوقعة وماذا تفعلين
| الرسالة (أو معناها) | السبب المرجّح | الفعل |
|---|---|---|
| `relation "..." already exists` عند 1 | المشروع ليس فارغًا أو نُفِّذ الملف سابقًا | لا تعيدي. نفّذي فحص القسم 3 وأرسلي نتيجته |
| `relation "public.audit_log" does not exist` أو `...staff_profiles...` عند 5 | لم يُنفَّذ 1 قبله | نفّذي 1 و2 أولًا |
| `permission denied` / `must be owner` | تنفيذ بدور غير مالك القاعدة | استعملي SQL Editor داخل لوحة Supabase (الدور الافتراضي postgres) لا أداة خارجية |
| `ABORT:` أول سطر في 3 | المحرر قسّم الأوامر على معاملات | لم يُنفَّذ شيء؛ أرسلي الرسالة |
| `ERROR: لا حذف ...` أو `لا يُسمح بـ...` أثناء 3 | حارس حماية يعمل (قد يكون جزءًا من الاختبار) | لا تقلقي؛ المهم الملخّص `RESULT:` النهائي |
| `FAIL` في 6 رقم 7 أو 8 | صلاحيات `log_audit_as` لا تطابق المتوقع (مثلًا منحتها Supabase افتراضيًا لـauthenticated) | أرسلي الصف؛ لا تمنحي ولا تسحبي بيدكِ |
| `bootstrap_staff` ينفي وجود المستخدم | لم تُنشئي المستخدم في Authentication أولًا أو البريد مختلف | أنشئيه بالبريد نفسه ثم أعيدي |
| أي خطأ لم يُذكر | — | انسخيه كما هو + اسم الملف الذي كنتِ تنفّذينه |

## 7) ما لا تغطيه ملفات SQL (لن أفعله دون موافقتكِ)
- **Cloudflare R2:** حاوية خاصة ومفتاح محصور بها وCORS (PUT للرفع وGET لتنزيل الأرشيف من المتصفح): `docs/phase5/R2_INTEGRATION_AR.md`.
- **نشر الخادم** (دالة Edge أو Worker) وربطه بقاعدة PostgreSQL من الخادم (لا يوجد بعد مشغّل إنتاجي للقاعدة): قرار استضافة معلّق.
- **متغيرات بيئة الخادم** (أسماء فقط، قيمها أسرار تُحقن عند النشر ولا تدخل الحزمة ولا Git): `SUPABASE_URL`، `SUPABASE_ANON_KEY`، `R2_ACCOUNT_ID`، `R2_BUCKET`، `R2_ACCESS_KEY_ID`، `R2_SECRET_ACCESS_KEY`، `TEACHER_CODE_PEPPER`، `TEACHER_PIN_PEPPER`، `TEACHER_IP_PEPPER` (كل منها ≥ 32 محرفًا ومختلف عن الآخر)، `ALLOWED_ORIGIN`.
- **الواجهة:** `.env.local` بالمفاتيح العامة فقط، و`VITE_TEACHER_API_URL` بعد نشر الخادم (انظر `env-local-template.txt`).

# تشغيل الواجهة على Windows لمعاينة التصميم
1. ثبّتي Node.js LTS (20 أو أحدث) من nodejs.org، ثم أعيدي فتح PowerShell.
2. افتحي PowerShell **داخل مجلد المشروع** (بعد فك الـZIP: في المستكشف ادخلي المجلد ثم اكتبي `powershell` في شريط العنوان واضغطي Enter).
3. `npm install` (مرة واحدة، يحتاج إنترنت؛ ليس `npm ci` لأن ملف القفل غير محدَّث بعد)، ثم `npm run dev`.
4. افتحي العنوان الظاهر (غالبًا `http://localhost:5173`). **ما تتوقعينه:** صفحة الدخول. الصفحات الحالية تعمل ببيانات وهمية.
5. للإيقاف: `Ctrl+C` في PowerShell. إن ظهر خطأ فانسخيه كما هو.
معاينة بلا تثبيت: انقري مرتين على `review\athar-ui-review.html`.
