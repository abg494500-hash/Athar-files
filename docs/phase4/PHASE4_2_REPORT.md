# المرحلة 4.2 — طبقة تخزين قابلة للتبديل + تخزين وهمي + معالجة R-02

**الحالة:** اكتُبت وفُحصت بما أتيح هنا (انظر «ما فُحص»). المرحلة 4.3 لم تبدأ، بانتظار مراجعتك.
**لم يُربط ولم يُختبر أي رفع إلى خدمة حقيقية.** التخزين الوهمي يعيش في ذاكرة المتصفح ويضيع عند تحديث الصفحة، ولا يثبت أن رفع الملفات لمزوّد حقيقي يعمل.

## ما أُضيف (`src/lib/storage/`)
| الملف | الوظيفة |
|---|---|
| `adapter.ts` | عقد `StorageAdapter` (`put`، `get`، `delete`) لا يفترض مزوّدًا ولا طريقة رفع (DP-03 معلّق). `DeletionAuthorization` نوع **لا يوجد له مُنشئ** في المرحلة 4 (A-44) |
| `memory.ts` | التخزين الوهمي: لا يكتب فوق مفتاح موجود، يرفض الفارغ وما يتجاوز حد المزوّد، يدعم الإلغاء، يحسب SHA-256، ويرفض `delete` دائمًا (`delete_not_implemented`) |
| `settings.ts` | إعدادات الحد والأنواع، الحد الفعلي = الأصغر بين الإعداد وحد المزوّد، فحص الملف، نص الحد للعرض |
| `sha256.ts` | SHA-256 عبر `crypto.subtle` وإلا تنفيذ JavaScript خالص |
| `keys.ts` | مفاتيح مؤقتة (`pending/...`) ونهائية (`files/.../vN.ext`) آمنة ضد «..» والشرطات |
| `errors.ts` | رموز أخطاء ثابتة ورسائل عربية، والحد يُمرَّر نصًا (لا قيمة ثابتة) |
| `StorageContext.tsx` | سياق React (`StorageProvider`/`useStorage`) بتخزين وهمي وإعدادات افتراضية |

## معالجة R-02 (في المصدر)
- حُذف الثابت `MAX_FILE_BYTES` (100 MiB) و`validateFile` و`TYPES_LABEL` و`ACCEPT_ATTR` من `src/lib/files.ts`.
- حد الحجم والأنواع **إعدادات**: القيمة الافتراضية **مؤقتة 50,000,000 بايت غير نهائية** (A-39)، وتطابق بذرة `database/001_schema.sql`.
- نافذة التسليم تقرأ الحد والأنواع من الإعدادات وحد المزوّد، فنص «الحد الأقصى» ديناميكي.
- تجاوز اختياري للتطوير المحلي: متغير `VITE_ATHAR_MAX_FILE_BYTES` (يُتجاهل إن لم يكن عددًا صحيحًا موجبًا). مشروح في `docs/RUN_GUIDE.md`.
- النافذة تحفظ الملف عبر `adapter.put` وتمرّر البصمة ومفتاح التخزين إلى `store.submit` بدل البصمة الوهمية؛ وإن لم تصل بصمة تبقى الوهمية (للروابط والبيانات التوضيحية).
- **حالة R-02: عولج في المصدر والفحص المتاح هنا، والتحقق الكامل معلّق** (لم يُشغَّل `vitest` ولا `tsc -b` ولا البناء). `review/athar-ui-review.html` **لم يُعَد بناؤه ويعرض نصًّا قديمًا (100 ميغابايت)**؛ يُعاد بناؤه بـ`npm run build:review`.

## ما لم يُفحص (ولا يصح الادعاء به)
- `npm test` الحقيقي (vitest + jsdom)، ومنه اختبارات الواجهة الـ19 بعد تعديل `SubmitDialog`. المتوقع نظريًا 52 ناجحًا (31 + 21) **غير مؤكد**.
- `tsc -b` للمشروع كله (أنواع React وسياق الواجهة وتمرير الحقول الجديدة).
- البناء (`npm run build`) والتشغيل في المتصفح، ومسار رفع ملف فعلي عبر النافذة في المتصفح.
- أي رفع إلى مزوّد حقيقي (لا يوجد مزوّد مربوط).
- SQL وRLS (لم يُنفَّذا على PostgreSQL، كما في 4.1).

## خطر معروف
حساب SHA-256 لملف كبير على المتصفح يعتمد على `crypto.subtle` (سريع)، وإلا فالتنفيذ الخالص (~35 ثانية للـ1 GB تقريبًا بتقدير خطي من القياس، غير مقاس فعليًا). حد الملف الفعلي لن يتجاوز ما يختبره V-xx لاحقًا.
